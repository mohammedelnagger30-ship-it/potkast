# Sada — منصة بودكاست عربية

واجهة React + Vite + Tailwind، والبيانات على Supabase.

## تشغيل المشروع

```bash
npm install
npm run dev        # http://127.0.0.1:5173 (أو 5174 لو المنفذ مشغول)
npm run build
npm run preview
```

## الكتالوج الحقيقي

كل بيانات المقدّمين والبودكاست والحلقات حقيقية، مصدرها Apple Podcasts + خلاصات RSS العامة:

- 82 مقدّم (ثقافة، تقنية، صحة نفسية، لياقة، أعمال، تنمية ذاتية، تاريخ، دين، أطفال، فلسفة، علاقات…)
- 766 بودكاست/سلسلة
- 63,800 حلقة (بعناوين ووصف وتاريخ ورابط mp3 أصلي؛ المدة تُعرض عندما تتوفر في الخلاصة)

### تحديث الكتالوج

```bash
# معاينة بدون كتابة
node scripts/import-real-catalog.mjs --dry

# استيراد فعلي — يستبدل كل المحتوى (يحتاج صلاحية كتابة مؤقتة)
node scripts/import-real-catalog.mjs

# إضافة مقدّمين جدد فقط، من غير ما نمسح الموجود
node scripts/import-real-catalog.mjs --append
```

قبل الاستيراد شغّل `supabase/enable_seed_writes.sql` في SQL Editor،
وبعده شغّل `supabase/disable_seed_writes.sql` لإزالة صلاحية الكتابة المؤقتة.

`supabase/real_podcasts.sql` و`supabase/full_setup.sql` للـ schema فقط —
لا يحتويان بيانات كتالوج.

## الصفحات

- `/hosts` — كل المقدّمين مع عدد البودكاست والحلقات
- `/hosts/:slug` — صفحة المقدّم: قسم «الموجزات» لكل دورة، وقسم «المحتوى الكامل» بكل الدورات وكل الحلقات كاملة (تحميل تدريجي أو زر «عرض كل الحلقات» بلا حد أقصى للمدة)، مع شريط تقدّمك مع هذا المقدم
- `/podcasts/:id` — صفحة البودكاست مع كل حلقاته (تحميل تدريجي) وزر «تنزيل السلسلة»، وزر «تنزيل» بجانب كل حلقة
- `/downloads` — إدارة التنزيلات (إيقاف/إعادة/حذف)، المساحة المستخدمة، والتقدّم الكلي لكل مقدم
- `/profile` — ملخّص التقدّم الكلي وتقدّم المقدمين، والصورة والاسم والألوان
- `/settings` — إعدادات الحساب والمظهر وحجم الخط وأهداف التعلّم وتحديثات التطبيق
- `/updates` — مركز التحديثات: النسخة الحالية، آخر نسخة منشورة، سجل الإصدارات، وتنزيل/تثبيت APK جديد من جوه التطبيق
- `/player` — مشغّل ملء الشاشة مع قائمة التشغيل والسرعة والتكرار

## الاستماع بدون إنترنت

- الملفات تُحفظ على جهاز المستخدم في IndexedDB (أو في cache الـ Service Worker للمصادر اللي ما بترسلش CORS)، وما بتترفعش لأي سيرفر.
- زر «تنزيل» بيظهر بجانب كل حلقة، وزر «تنزيل السلسلة» بينزّل كل حلقات البودكاست. التنزيلات بتشتغل بطابور (حالتين في نفس الوقت) مع إمكانية الإيقاف وإعادة المحاولة.
- بعد أول فتح، واجهة التطبيق نفسها بتتخزن في الـ Service Worker، فأي صفحة بتفتح من غير نت.
- التقدّم بيتحسب من `listening_history`: نسبة الحلقات المكتملة لكل مقدم، ونسبة إجمالية لكل الكتالوج، مع نسخة محفوظة محلياً عشان تظهر حتى لو السيرفر مش متاح.

## حجم الخط والوضع البسيط

- في `/settings` فيه مفتاح «حجم خط ثابت داخل التطبيق»: لما يتفعّل، WebView بيستخدم `setTextZoom(100)` والـ CSS بيثبّت `font-size` على 16px، فالوضع البسيط في شاومي أو تكبير خط النظام ما بيغيّرش شكل Sada.
- الإعداد بيتحفظ في `SharedPreferences` (`sada_text_scale`) و`localStorage` (`sada:fixed-text-scale`)، وبيتحط قبل أول رسم للواجهة. لمّا يتطفا، التطبيق يرجع يتبع `fontScale` بتاع النظام.
- `fontScale` و`density` متضافين لـ `configChanges` عشان تغيير إعدادات الجهاز ما يعملش restart للWebView.

## نظام التحديثات

- مصدر الحقيقة هو GitHub Releases: أي ريلز جديد بيبقى تلقائياً هو «آخر تحديث» لكل نسخة مثبّتة، من غير ملف manifest منفصل.
- التطبيق بيفحص الإصدار كل 6 ساعات وعند فتحه من جديد، ويخزّن النتيجة محلياً (`sada:update-cache`) عشان يشتغل حتى لو الشبكة مش متاحة.
- لما يطلع إصدار أحدث: بيظهر تنبيه في الهيدر وإشعار في مركز الإشعارات، ونافذة واحدة توضّح جديد النسخة وتقدر تنزّلها وتثبّتها من جوه التطبيق.
- على أندرويد بيتم التنزيل عبر `DownloadManager` (بيكمل في الخلفية) والتثبيت عبر موافقة «تثبيت تطبيقات من مصادر خارجية». على المتصفح بيتم التنزيل كملف APK عادي.
- لازم يبقى `versionName` في `android/app/build.gradle` مساوي لتاج الريليز (مثلاً `1.2.0` ↔ `v1.2.0`)، وبعد نشر الريليز بيتم تعديل `BUNDLED_VERSION` في `src/lib/appUpdate.ts` للمطابقة.
- لمعاينة واجهة التحديث في وضع التطوير: `localStorage.setItem('sada:update-force-version', '1.0.0')`.

> ملاحظة: `"تحميل"` في الواجهة معناها تحميل/عرض بيانات من Supabase. أما الحفظ الفعلي للاستماع أوفلاين فسمّيناه **«تنزيل»**.
